# 2026-08 — monthly summary

Summarizes the 19 session entries from August 2026, now in [`2026-08/`](2026-08/). Current status
lives in [`roadmap-tracker.md`](../../roadmap-tracker.md); this file records what happened.

## 3A — Third-party API (ADR-012) and connector runtime

- Connector polling scheduler shipped for issue #366 (ADR-009 Decision #7): BullMQ reconcile
  ticker, `connector-poll-worker.ts`, cursor-state advance; review and security-review each caught
  a repeatable-job scheduling bug plus an interval floor and event-size caps.
- Connector kill switch shipped for issue #367 (ADR-009 Decision #9): soft-disable columns on
  `connector_credentials`, a `PATCH /connectors/:connectorId/disabled` route, and enforcement
  across the webhook gateway, outbound worker and poll scheduler; fixed a fail-open bug and a
  TOCTOU race in the audit trail.
- ADR-012 Phase B (Core Ticket API) merged: dual-identity auth middleware (#461), list workflows
  (#464), ticket detail (#465), ticket create (#466) — closed a ticket-existence-oracle leak and a
  hardcoded `actorType` bug in entity-engine along the way.
- ADR-012 Phase F Phase 1 (API access-logs screen, PR #489): centralized allow/deny outcome
  classification, an admin-only access-logs route and UI, and a retrofit adding audit entries to
  comments/children/attachment-reference routes that had none before; fixed a bug where audit rows
  recorded the acting person instead of the API key.
- ADR-012 Phase G hardening, three phases, all merged: Phase 1 (PR #495) added 3-tier rate
  limiting, JWT `iat` freshness, PII redaction and TLS enforcement; Phase 2 (PR #499) added
  idempotency-key support (RFC 8785 canonicalization, Redis lock, 24h cache); Phase 3 closed the
  gate with access-log retention rollup, tenant-purge anonymization of `admin_audit_log`, and a
  full cross-phase `/security-review` that found and fixed a missing RLS policy on the new rollup
  table.
- Post-Phase-G end-to-end testing (via a new reference client, OWTester) found two real bugs unit
  tests missed: third-party transitions always passed `actorRoles: []`, making every real seeded
  workflow's transition endpoint unreachable (fixed, PR #514, additive baseline `"user"` role); and
  the `canonicalize` ESM package crash-looped the compiled server (fixed, PR #513). Both merged
  2026-08-28.
- Review follow-ups on Phase E (#490–#494, #496–#498: TOCTOU, test-state and tenant-filter fixes,
  Redis counter and timeout races) were all closed by 2026-08-27. #457 (key rotation dropping
  third-party application metadata) closed 2026-08-22.

## Platform fixes — DB privileges, migrations, tooling

- Closed an `app_user` over-grant bug class: `ALTER DEFAULT PRIVILEGES FOR ROLE migration_user`
  silently grants full DML to every new table, undoing a bare `GRANT SELECT`. Fixed with explicit
  `REVOKE` migrations on `connector_definitions` (0060), `modules`/`tenants`/`platform_settings`/
  `admin_audit_log` (0061, issues #404–#406), and column-scoped `UPDATE` on `tenants` (0062, issue
  #408). Also found that CI migrates as a superuser, not `migration_user`, so isolation tests for
  this whole bug class pass in CI for the wrong reason — raised to the human, not fixed (would
  require editing `.github/workflows/`, off-limits).
- Issue #116 closed as resolved-via-documentation (async export already shipped); fixed a mock
  string typo (#385), a missing type-assertion comment (#386).
- Issue #437: added the missing `apps/*` → `apps/*` eslint boundary rule plus a dependency-cruiser
  mirror; three review rounds fixed a path-depth miss, a same-name-subfolder false positive, and a
  dependency-cruiser empty-siblings edge case.
- api_keys length-limit hardening: application metadata columns (#445, migration 0070), then
  `zitadel_client_id` (#451, migration 0071) — the latter later broke on already-migrated DBs once
  migration 0072 renamed the column, filed as #474 and fixed with a branching forward migration
  (0075) that handles both pre- and post-rename states.
- Issue #450: added a loopback-only Redis host port mapping so host-mode `pnpm test` works;
  presented the shared-host security trade-off to the human, shipped loopback-only. Filed #454
  (Postgres host binding) and #455 (OpenBao exposure) as follow-ups; both closed 2026-08-24.
- Issue #436 (outbox-poller isolation flake): first found and fixed an unrelated deterministic
  failure — migration 0073's journal timestamp was smaller than 0072's, so it was silently skipped
  on incrementally-migrated DBs (also found the same bug class latent in migration 0071, filed as
  #474). With a clean baseline restored, the actual flake turned out to be a vitest 5000ms default
  timeout with no margin against a 100-iteration poll loop — fixed by setting an explicit 15s
  per-test timeout, no production code changed.

## Decisions

- ADR-015 (observability + compliance) accepted 2026-08-26: error tracking must be pluggable
  across Sentry/GlitchTip/Bugsink/none rather than fixed to one vendor; plan-limit enforcement
  degrades per-metric rather than hard-blocking, surfaced via the network-status banner plus a
  Novu notification to tenant admins.
- Redis host port mapping shipped loopback-only rather than deferring, matching this stack's
  existing dev-security posture (OpenBao's `0.0.0.0` exposure, committed Postgres dev password)
  instead of introducing a new risk class.
- Third-party transition role mapping: grant only the baseline `"user"` role, and only after
  `hasTransitionAccess` already confirmed access — additive to the existing gate, never a
  substitute, never `"admin"`/`"agent"`.
- CI's migration role gap (superuser vs. `migration_user`) left unfixed and handed to the human —
  fixing it means editing `.github/workflows/`, which is off-limits for autonomous work.
