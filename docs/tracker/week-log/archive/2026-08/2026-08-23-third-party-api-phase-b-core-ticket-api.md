### Completed this session

#### PR B1 (#461) — dual-identity auth middleware

- `requireActingPerson()` (`packages/auth/src/dual-identity.ts`): verifies a second identity
  (a real "acting person") alongside the API key on every third-party ticket-lifecycle request —
  `aud` claim match against the key's registered `zitadel_client_id`, 15-minute `iat` freshness
  independent of Zitadel's own expiry, tenant/org match, uniform 401 across every failure case
  (spec R14 — no distinguishing detail).
- Fixed a GitHub Advanced Security (CodeQL) HIGH finding: dropped `apiKeyId` from a clear-text
  warn log line.
- Added a test-fixture short-circuit mirroring `requireAuth`'s existing precedent.

#### PR B2 (#464) — `GET /api/v1/workflows`

- Access-list-filtered, paginated, deterministic ordering; returns only `id`/`name`/
  `entityTypeId`.

#### PR B4 (#465) — `GET /api/v1/tickets/:id`

- Access-list gated via the existing `hasEntityAccess` helper. Isolation testing caught a
  ticket-existence-oracle regression (nonexistent vs. access-denied tickets returned different
  error bodies) — fixed by catching `ENTITY_NOT_FOUND` explicitly and returning a byte-identical
  404 body for both cases.

#### PR B3 (#466) — `POST /api/v1/tickets`

- Always forces the workflow's initial state — the create schema simply omits `state`/
  `currentState` fields so Zod strips them, no rejection path.
- New ingress guard (`validate-fields-payload.ts`): 100KB size cap, depth cap 8, rejects null
  bytes/control chars.
- New nullable `admin_audit_log.acting_person_id` column so the audit trail can search by the
  real person independently of the API key (`packages/db/migrations/0073_admin_audit_log_acting_person.sql`
  — see migration-collision note below for why it's 0073, not 0072).
- Fixed a latent bug in `entity-engine`'s `createEntity`: `actorType` was hardcoded to `"user"`,
  ignoring an already-existing `input.actorType` field the sibling engine functions already
  respected.
- R10 (admin-UI "Agent" tag / "Auto-generated by [Application Name]" banner) explicitly deferred
  to a fast-follow PR, confirmed with the human — the application name isn't cheaply available at
  ticket-read time (lives on `api_keys`, only joinable via the audit log's create entry).

columns) had already claimed migration index `0072`

merge-main-into-branch fixes directly to the B2/B4 branches — diffed his resulting tree against
ours post-rebase and confirmed byte-identical content before the force-push, so nothing of his
