# 2026-11-05 — PATCH on-call schedule 404 on mid-transaction delete (#1121)

## Done

- `apps/api/src/routes/admin/on-call-schedules.ts`: the PATCH handler returns `not_found` (404) when its UPDATE matches no row, instead of 200 `{data:null}`. This covers a soft-delete committed between the `peek` SELECT and the UPDATE. The audit entry is skipped in that case.
- Unit test added for the empty-UPDATE path.

## Not done: #1122 (rotation sweeper filter)

The issue's proposed `next_starts_at <= now + lead` filter would stop retrying failed notices:
`sendNoticesForRotation` is documented to retry on the next run, and a rotation whose window was
just generated has `nextStartsAt` pushed a full cycle ahead, so it would drop out of the sweep
while its notice is still unsent. A correct fix also has to select rotations with an un-noticed
window starting within the lead, which needs the sweeper role to read `on_call_schedules` (a grant
migration) and a design call. Left open with that finding.
