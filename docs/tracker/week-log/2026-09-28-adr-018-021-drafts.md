# 2026-09-28 — ADR-018/019/020/021 drafted as Proposed; stale ADR citations fixed (#695)

**Session type:** Docs (ADR backlog)
**Issues:** #695, #622, #620, #614
**Branch:** `docs/PLAT-695-adr-drafts`

Four ADRs the backlog had been waiting on, drafted from shipped code and the confirmed direction
issues. They are **Proposed**: a human (Engineering Lead, and PrabhuVijit for ADR-021) accepts or
edits them in review.

- **ADR-018 — AI layer (3C).** The number was reserved in #614. It sets out seven decisions:
  - features are assistive only; generated rules are data, validated and saved disabled;
  - `packages/ai` is the single gateway, carrying tenant, feature and actor;
  - per-tenant metering and rate limits ship with the first feature (#618);
  - context is limited to what the acting user can read, through a public-field allowlist;
  - outputs carry provenance and coverage disclosure (#609);
  - the first slice is #609/#627/#614; retrieval, MCP and delegated identity are deferred;
  - model choice is configuration, gated by a small eval set.

  **Accepting it does not start 3C**; that stays a human scope decision.

- **ADR-019 — reporting tenant isolation (3G).** Ratifies Stages 1–2 as shipped:
  - `DB_CONNECTION_MUTATOR` stamps `app.tenant_id` so existing RLS applies;
  - `analytics_user` is least-privilege by table and column (migrations `0112`–`0124`);
  - payloads are excluded through derived projections;
  - own-rows is a restrictive policy;
  - Stage 1 uses 60 s guest passes (capped at 90 s);
  - Stage 2 (SSO + SQL Lab) is off by default.

  It states that **Stage 2 must stay disabled until a pending security review closes**. It also
  flags that shipped masking uses projections rather than option C's stored redacted copy, which
  needs owner sign-off.

- **ADR-020 — module ownership (3H).** Customer-neutral. It covers:
  - the classification test for coordination-native vs. domain-deep modules;
  - ownership per class;
  - new flagship workflows shipping as separate `optional` modules (the #680 precedent);
  - verticals built only on a concrete ask;
  - existing bespoke modules staying as production config.

  Rows that #622 doesn't state explicitly are marked as drafter inference for humans to confirm.

- **ADR-021 — ticket relations and participant access.** Records what shipped rather than what
  `docs/ticket-relations-design.md` proposed. `ticket_participants` was never built; access is the
  per-ticket `__accessUsers` map plus `access_requests`. Only `parent_of`/`child_of` and
  `references`/`referenced_by` carry engine meaning; other relation types are free-text labels.
  Unbuilt design items are listed under Deferred Decisions.
